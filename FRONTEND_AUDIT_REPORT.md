## 1. Executive Summary

A comprehensive architectural and functional audit of the `frontend/` repository was performed. The frontend is a modern React 19 + TypeScript application bundled with Vite 8 and Tailwind CSS 4. The initial baseline builds cleanly (`tsc -b && vite build` in 2.90s) and passes linter checks (`oxlint` with 0 warnings/errors).

However, the existing user interface is implemented as a single monolithic component (`App.tsx`, 628 lines) with basic tab switching between Chat, SQS Inspector, Evidence, Reports, and Settings. It currently lacks dedicated SOC operational views (Overview Dashboard with KPI metrics and attack trends, Security Event Explorer for interactive telemetry browsing, dedicated Investigation Workspace, ATT&CK Threat Analysis view, and an Audit Trail view).

This audit identifies the current repository structure, existing strengths, architectural gaps, and the execution blueprint for upgrading the application into an enterprise-grade SOC investigation dashboard.

## 3. Detailed Component & System Analysis

### 3.1 Existing Pages and Components
- **`src/App.tsx` (628 lines):**
  - Top Navigation Bar: Application branding (`SENTINEL AI / SIH25173`), mandatory persistent red `SYNTHETIC DATA MODE` banner (Sections 3 & 16 compliance), provider indicator, and backend operational status.
  - Tab Bar: 5 tabs (`chat`, `inspector`, `evidence`, `reports`, `settings`).
  - Chat View: Basic chat thread, example query chips, user/assistant message bubbles, evidence ID badges, follow-up suggestion buttons, query execution input.
  - SQS Inspector: JSON viewer of the `SentinelQuerySpec` generated by LangGraph.
  - Evidence View: Active finding cards (severity, classification, evidence IDs) and supporting event ID pill cloud.
  - Reports View: Export buttons for PDF, JSON, and CSV; table of generated reports with SHA-256 integrity checksums and download links.
  - Settings & Status View: Provider name, data mode, provider health status, and ECS field registry mappings.

### 3.2 Routing Configuration
- **Status:** In-memory tab-state routing via `useState<'chat' | 'inspector' | 'evidence' | 'reports' | 'settings'>`.
- **Finding:** No client-side browser URL router (`react-router-dom`) is currently installed. Tab-based view switching is lightweight, avoids hash-routing issues in static deployments, and maintains investigation state cleanly across tab switches. Expanding the active view union to cover all 7 requested SOC modules will provide a seamless single-page application experience.

### 3.3 API Client and API Service Modules
- **`src/services/api.ts`:**
  - Configures `API_BASE = `${import.meta.env.VITE_API_BASE_URL || ''}/api/v1``.
  - Implements: `fetchProviderStatus()`, `createConversation()`, `listConversations()`, `getConversationDetail()`, `sendChatMessage()`, `generateReport()`.
  - **Gaps Identified:**
    1. No client function for `POST /api/v1/queries/execute` (required for Security Event Explorer and Overview metrics).
    2. No client function for `POST /api/v1/queries/preview` (validating ad-hoc SQS queries).
    3. No client function for `GET /api/v1/health/ready`, `GET /api/v1/health/db`, or `GET /api/v1/health/live`.
    4. No authentication client functions (`login()`, `getCurrentUser()`).
    5. Missing centralized error handling, HTTP status parsing, and automatic Bearer JWT injection.

### 3.4 Authentication Implementation
- **Status:** Unauthenticated / Dev Mode.
- **Backend Capability:** The FastAPI backend implements `POST /api/v1/auth/login` and `GET /api/v1/auth/me`. In development mode (`APP_ENV=development`), missing `Authorization: Bearer <token>` automatically falls back to the auto-seeded demo user (`analyst@sentinel.ai`).
- **Frontend State:** The frontend currently makes unauthenticated requests. It lacks a login modal/page, JWT token storage in `localStorage`/`sessionStorage`, and an active user profile display.

### 3.5 Dashboard Components
- **Status:** Missing dedicated SOC executive dashboard.
- **Required:**
  1. Total security events counter.
  2. Critical, High, Medium, and Low alert distribution cards.
  3. Risk score distribution meter and breakdown.
  4. Attack category distribution (Authentication, Process, Malware, Network).
  5. Recent security events feed.
  6. Quick investigation launcher.

### 3.6 Charts and Visualization Libraries
- **Status:** Tailwind CSS flexbox/bar widgets and SVG indicators; `lucide-react` icons.
- **Finding:** Clean responsive CSS/SVG charts (bar distributions, severity breakdown bars, timeline progress, risk gauges) provide rapid rendering with zero external bundle bloat and 100% theme consistency with the SOC dark palette.

### 3.7 State Management
- **Status:** React local state (`useState`, `useEffect`).
- **Finding:** Sufficient for conversational state, active investigation context, and filter states without adding third-party state library dependencies. Can be structured into dedicated custom hooks and modular component props.

### 3.8 Existing Design System
- **Colors:**
  - Background: Dark SOC palette `#090d16` (slate-950/deep navy)
  - Surfaces/Cards: `#0f172a` (slate-900), `#1e293b` (slate-800)
  - Borders: `#334155` (slate-700), `#1e293b`
  - Text: `#f8fafc` (slate-50), `#cbd5e1` (slate-300), `#94a3b8` (slate-400)
  - Accent / Primary: `#38bdf8` (sky-400), `#2563eb` (blue-600)
  - Warning / Synthetic: `#450a0a` / `#ef4444` / `#fca5a5` (red-500/900)
  - Severity Badges: Critical (`#ef4444`), High (`#f97316`), Medium (`#eab308`), Low (`#3b82f6`), Info (`#64748b`)
- **Typography:** System UI monospace and sans-serif fonts, crisp telemetry hierarchy.

## 5. Architectural Recommendations

1. **Modularize the Component Hierarchy:**
   Break `App.tsx` into clean, maintainable modular components in `src/components/`:
   - `Sidebar.tsx`: Professional vertical SOC navigation bar with module icons, connection status, and active user card.
   - `Navbar.tsx`: Top header with system health indicator, data mode disclosure badge, and provider info.
   - `OverviewDashboard.tsx`: Executive SOC dashboard with event totals, severity gauges, category metrics, and quick actions.
   - `ChatAssistant.tsx`: Enhanced conversational investigation workspace with LangGraph streaming UX and evidence references.
   - `EventExplorer.tsx`: Security event search and filter table connected to `POST /api/v1/queries/execute`.
   - `InvestigationWorkspace.tsx`: Comprehensive case management workspace with risk analysis and findings.
   - `ThreatAnalysis.tsx`: MITRE ATT&CK matrix view, correlation engine findings, and detection rules.
   - `ReportsView.tsx`: Multi-format report generator with cryptographic SHA-256 checksums and verified download links.
   - `AuditTrail.tsx`: Audit and execution history log with query execution details.
   - `AuthModal.tsx`: Analyst authentication modal supporting JWT login and demo profile toggle.

2. **Enhance API Service:**
   Expand `src/services/api.ts` with typed methods for `executeQuery`, `previewQuery`, `checkHealth`, `login`, and `getMe`, complete with Bearer token header handling and connection fallback.

3. **Preserve Strict Invariants:**
   - Zero mock data in completed features: All telemetry and event counts are sourced directly from the backend via `POST /api/v1/queries/execute` and `POST /api/v1/chat`.
   - Persistent `SYNTHETIC DATA MODE` labeling across all views and report downloads.
